# Max Bot - Инструкциональный документ

## Обзор проекта

Max Bot - это бот для Max Messenger на языке Go, предназначенный для автоматизации взаимодействия в корпоративных чатах. Основная функция - отслеживание информации о больничных и отпусках сотрудников с использованием AI (OpenRouter) для анализа сообщений.

### Основные возможности:
- Отправка и получение сообщений на русском языке
- Базовая обработка команд (/help, /echo)
- Поддержка групповых чатов с хранением сообщений
- Специальные команды администратора (/last, /stat)
- Обработка упоминаний бота в групповых чатах
- Анализ сообщений с помощью AI для выявления информации об отсутствии сотрудников
- Отправка сообщений с inline-кнопками для подтверждения действий

## Команды бота

### Для всех пользователей (в личных сообщениях):
- `/help` - Показать список доступных команд
- `/echo [text]` - Повторить текст за пользователем

### Для администратора (ADMIN_USER_ID):
- `/help` - Показать все команды (включая администраторские)
- `/echo [text]` - Повторить текст
- `/last` - Последние 5 сохранённых сообщений из текущего чата
- `/stat` - Статистика сообщений по всем чатам

### Поведение в групповом чате:
- При упоминании (@bot или /) отвечает: "Извините, я пока не умею разговаривать."
- Все сообщения сохраняются для последующего анализа
- На другие сообщения не реагирует

## AI анализ сообщений

Бот анализирует сообщения из отслеживаемого чата (CHAT_ID) на предмет информации об отсутствии сотрудников:

1. Сообщение отправляется в OpenRouter API с промптом из `prompt.txt`
2. AI извлекает структурированные данные:
   - Тип отсутствия (Больничный/Отпуск)
   - Должность и ФИО сотрудника
   - Даты начала и окончания
   - Статус (Начало/Окончание/Продолжение)
3. При валидном результате отправляется уведомление администратору с кнопками "Принять"/"Отмена"

### Структура MessageAnalysis:
```go
type MessageAnalysis struct {
    OriginalMessage string
    IsValid         bool
    Employee        struct {
        Position  string
        FullName  string
    }
    AbsenceType string
    Dates       struct {
        StartDate string
        EndDate   string
    }
    Status     string
    Substitute string
}
```

## API Max Messenger

### Отправка сообщений:
- **URL**: `https://platform-api.max.ru/messages`
- **Метод**: POST
- **Параметры**: `chat_id` (query parameter)
- **Заголовок**: `Authorization: <token>`

### Формат сообщения с клавиатурой:
```json
{
  "text": "Сообщение",
  "attachments": [
    {
      "type": "inline_keyboard",
      "payload": {
        "buttons": [
          [
            {
              "type": "callback",
              "text": "Кнопка",
              "payload": "action"
            }
          ]
        ]
      }
    }
  ]
}
```

### Известные ограничения API:
- ❌ Редактирование сообщений не поддерживается (PUT /messages/{id} возвращает 404)
- ❌ Удаление клавиатуры после нажатия кнопки невозможно
- ❌ Callback answer через POST /messages/callback не поддерживается (возвращает 404)

# Joomla Article Manager - Проект обновления статей Joomla

## Обзор проекта

**Joomla Article Manager** — это инструмент на Python для управления содержимым статей Joomla 3.10.12. Основное назначение — обновление расписания врачей на сайте медицинской организации через прямое обновление базы данных Joomla.

### Ключевые возможности

- **Получение содержимого статей** — извлечение HTML-контента через веб-интерфейс админки Joomla
- **Обновление статей** — запись нового содержимого напрямую в базу данных (`#__content`)
- **Токен-аутентификация** — защита PHP-скрипта на сервере через секретный токен
- **Работа с HTML-контентом** — поддержка таблиц, JavaScript, форматирования

### Архитектура

```
┌─────────────────────┐     HTTP POST      ┌─────────────────────┐
│  Python-скрипты     │ ──────────────────► │  update_article.php │
│  (локально)         │  (токен + данные)   │  (на сервере Joomla)│
└─────────────────────┘                     └──────────┬──────────┘
                                                       │
                                                       ▼
                                              ┌─────────────────────┐
                                              │  База данных Joomla │
                                              │  #__content         │
                                              └─────────────────────┘
```

## Установка и запуск

### Требования

- Python 3.6 или выше
- Доступ к админке Joomla (логин/пароль)
- FTP/SFTP доступ для загрузки PHP-скрипта

### Установка зависимостей

```bash
pip install -r requirements.txt
```

### Зависимости

| Библиотека | Назначение |
|------------|------------|
| `requests>=2.25.1` | HTTP-запросы |
| `beautifulsoup4>=4.9.3` | Парсинг HTML |

### Настройка конфигурации

1. Скопируйте шаблон:
   ```bash
   cp config_example.py config.py
   ```

2. Отредактируйте `config.py`:
   ```python
   SITE_URL = "https://your-site.com"
   ADMIN_URL = "https://your-site.com/administrator"
   USERNAME = "admin"
   PASSWORD = "your_password"
   API_TOKEN = "your_secret_token"  # Минимум 32 символа
   ```

### Загрузка PHP-скрипта

Загрузите `update_article.php` в корень сайта Joomla:
```bash
# Через FTP/SFTP или файловый менеджер
# Путь: /var/www/your-site/update_article.php
```

**Важно:** Токен в `update_article.php` (строка 15) должен совпадать с `API_TOKEN` в `config.py`.

## Использование

### Рабочий процесс

```bash
# 1. Получить текущее содержимое статьи
python3 get_article_content.py 1025 schedule.html

# 2. Отредактировать schedule.html в текстовом редакторе
#    - Добавить пометки об отпуске/больничном
#    - Изменить расписание

# 3. Обновить статью на сервере
python3 update_article_remote.py 1025 schedule.html
```

### Команды скриптов

#### get_article_content.py

| Параметр | Описание |
|----------|----------|
| `article_id` | ID статьи в Joomla |
| `output_file` | Имя файла для сохранения (по умолчанию: schedule.html) |

**Примеры:**
```bash
python3 get_article_content.py 1025 schedule.html
python3 get_article_content.py 1007 article.html
```

#### update_article_remote.py

| Параметр | Описание |
|----------|----------|
| `article_id` | ID статьи для обновления |
| `content_file` | Файл с новым содержимым (HTML) |

**Примеры:**
```bash
# Тест (добавляет маркер обновления)
python3 update_article_remote.py 1025

# Обновление из файла
python3 update_article_remote.py 1025 schedule.html
```

### Массовое обновление

```bash
#!/bin/bash
for id in 1025 1026 1027; do
    python3 update_article_remote.py $id schedule.html
done
```

### Через CURL напрямую

```bash
curl -X POST "https://your-site.com/update_article.php?token=YOUR_TOKEN&id=1025" \
     -d "articletext=<p>Новое содержимое</p>"
```

## Безопасность

### Критические рекомендации

1. **Удалите `update_article.php` после использования!**
   - Скрипт даёт прямой доступ к обновлению статей
   - Не требует дополнительной аутентификации кроме токена

2. **Используйте сложный токен**
   - Минимум 32 символа
   - Комбинация букв и цифр

3. **Не коммитьте `config.py` в Git**
   - Используйте `.gitignore`
   - Храните секреты в безопасном месте

4. **HTTPS обязательно**
   - Токен передаётся в открытом виде
   - Используйте только HTTPS соединения

## Решение проблем

| Ошибка | Причина | Решение |
|--------|---------|---------|
| "Ошибка: неверный токен доступа" | Токены не совпадают | Проверьте `API_TOKEN` в `config.py` и `SECRET_TOKEN` в `update_article.php` |
| "Статья с ID не найдена" | Нет статьи с таким ID | Проверьте ID в базе данных или админке |
| "Ошибка соединения" | Сайт недоступен | Проверьте URL и сеть |
| "Could not find template isis" | Предупреждение Joomla | Не влияет на работу, можно игнорировать |
| Содержимое не обновляется | Кодировка файла | Сохраняйте файл в UTF-8 без BOM |
